# サブスク — Video Editor を SyncScout のプランの機能として付ける

2026-11-14 の打合せのまとめ。まだ実装していない。

---

## 1. 決まったこと

- 決済は **Stripe**（SyncScout で使っているもの）
- Video Editor は **SyncScout のプランに付く機能**として扱う。Video Editor 専用のアカウントやライセンスキーは作らない
- アカウントは **SyncScout のアカウント 1 つ**で両方を使う
- 値段は大きくないので、「Video Editor だけ欲しい人には SyncScout のプランが割高」という点は気にしない（単体プランは作らない）

---

## 2. 全体の形

```
Stripe                         SyncScout サーバー                Video Editor（アプリ）
───────────────────────────    ─────────────────────────────    ─────────────────────
Product: Pro / Team など       Webhook を受けて                  ブラウザで SyncScout にログイン
 └ Feature: video_editor  ──▶  アカウントの機能一覧を保存  ──▶  署名付きライセンスを受け取る
                               /editor/license で発行             オフラインでも期限まで使える
```

### Stripe

- **Entitlements（Features）** を使う。Feature を 1 つ作る（`lookup_key: video_editor`）
- Video Editor を付けたいプランの Product に、その Feature を付ける
- 付け外しは Stripe の管理画面で Product と Feature の紐付けを変えるだけ（コードの変更はいらない）
- 契約の開始・プラン変更・解約に合わせて、Stripe が機能を付けたり外したりする

### SyncScout サーバー

- Webhook `entitlements.active_entitlement_summary.updated` を受けて、アカウントの今の機能一覧を DB に保存する
- アプリ用の口 `POST /editor/license` を足す
  - `video_editor` があれば署名付きライセンスを返す（アカウント、機能、端末ID、有効期限 約 30 日）
  - なければ「プランに含まれていません」と、プラン変更の URL を返す
  - Webhook の取りこぼしに備え、発行のときに Stripe の API（active entitlements）で確かめ直すか、定期的に突き合わせる
- 署名は Ed25519 など。秘密鍵はサーバーだけが持ち、公開鍵をアプリに入れる

### アプリ（Video Editor）

| 項目 | 方法 |
|---|---|
| ログイン | 「ログイン」で普段のブラウザに SyncScout のログイン画面を開き、終わったら `syncscout-editor://` のリンクでアプリに戻る（OAuth + PKCE）。アプリにパスワード欄は置かない |
| 権利の確認 | `/editor/license` のライセンスを公開鍵で確かめる。オフラインでも確認できる |
| 更新 | ネットにつながったとき（起動時、1 日 1 回）に取り直す。期限まで途切れない |
| 保存 | ログイン状態を保つ情報は `safeStorage` で暗号化して保存 |
| 端末 | 1 アカウントの台数に上限を付ける（台数は未定）。アカウント画面から端末を外せる |
| 支払い | アプリの中では扱わない。Checkout / Customer Portal をブラウザで開く |
| 使えないとき | プロジェクトを開いて見るのはできる。**書き出しはできない**（データを人質にとらない） |
| 配布 | インストーラーは今のまま公開リポジトリで配る。使えるかどうかはアプリの中で決める。自動更新（`src/main/updater.ts`）はそのまま |
| 接続先 | Stripe には直接つながず、SyncScout サーバーとだけ話す（アプリに Stripe のキーを入れない） |

手を入れるところ:
- `src/main/license.ts`（新規）: ログイン、ライセンスの確認と更新、端末ID
- `src/main/index.ts`: `app.setAsDefaultProtocolClient` でリンクを登録し、`requestSingleInstanceLock` の `second-instance` で受け取る（Windows）。Mac は `open-url`
- 画面: ログイン状態の表示、書き出しボタンを権利で止める、「プランに含まれていません」からプラン変更へ飛ぶ

## 3. 流れ

### 新しく契約する人（SyncScout のアカウントが付く）

「Video Editor 付きのプランを契約する」＝「SyncScout のアカウントを作って、そのプランを契約する」なので、アカウントは最初から付いてくる。

1. 料金ページで Video Editor が付くプランを選ぶ
2. SyncScout のアカウントを作る（登録済みのメールならログインへ）
3. そのアカウントで Stripe Checkout へ（**アカウントを先に作り、支払いはあと**。決済と結びつかない購入を出さない）
4. Stripe が `video_editor` を付け、Webhook で DB に入る
5. 完了画面とメールに Video Editor のダウンロードリンクと「同じアカウントで使えます」を出す
6. アプリを起動 → ログイン → 使える

### すでに SyncScout を使っている人

- **Video Editor 付きのプランの人**: 何もしなくても使える。お知らせとダウンロードリンクを送る
- **付いていないプランの人**: Customer Portal か Checkout で上のプランへ。差額の日割りは Stripe が計算する
  - アプリの「プランに含まれていません」から、プラン変更へ直接飛べるようにする
  - SyncScout の中でも、使っている流れの中で案内する（「この場面をミーティング用の動画にするなら Video Editor」など）

## 4. 気をつけること（デメリット）

1. **オフラインのアプリがネットとサーバーに頼るようになる**
   最初のログインにはネットが要り、その後も約 30 日に 1 回はつながる必要がある。SyncScout のサーバーが止まると新しく使い始められない。
   → 猶予は長めに、期限が切れても見るのはできるようにする、期限の数日前にアプリで知らせる
2. **ライセンスの確認は破られうる**
   Electron の中身（asar）は書き換えやすく、全部手元で動くので改造されると全機能が使える。
   → 強いコピー防止はしない。自動更新・サポート・SyncScout 連携で正規に使うほうが楽、にする
3. **Entitlements は「付いている／いない」だけ**
   端末の数・チームで使える人数・お試し期間は自分で作る。Webhook の取りこぼしにも備える（2 章）
4. **お試し期間は Stripe の trial を使わない**
   プラン変更に trial を付けると契約全体がお試しになる。Video Editor だけ試してもらうなら、SyncScout の DB に期限付きの機能として持ち、`/editor/license` は Stripe の機能と DB のお試しの両方を見る
5. **今のプランに Feature を付けると、その契約者全員に一度に付く**
   意図どおりでなければ、別の Product / Price に分ける
6. **売上が見えにくい**
   セットだと Video Editor がどれだけ効いているか分かりにくい。`video_editor` を持つアカウントがアプリを起動したかを記録しておく
7. **チームプランとパソコンごとのアプリが合わない**
   1 アカウントを使い回されやすく、端末の上限を厳しくするとパソコンを替えるたびに困る。チームならメンバーごとにログインし、人数に上限を付けるのがきれい（作る量は増える）
8. **支払いが失敗している間（past_due）**
   機能が残るかは Stripe の督促の設定しだい。実際に試して確かめる。アプリ側はライセンスの期限が猶予になる
9. **今のテスター**
   無料・ログインなしだったので改悪に見える。前もって知らせ、しばらく無料などの優遇を付ける

### 課金を始める前に確認すること

- **ffmpeg（GPL）**: 別プロセスなのでアプリ本体は GPL にならないが、有料で配るならライセンス文と ffmpeg のソースを入手できるようにしておく（`docs/design.md` の「配布する場合は注意」）
- **H.264 のエンコード（libx264）**: 商用製品では特許料の対象になりうる。確認しておく
- **特定商取引法の表記**、消費税（Stripe Tax など）
