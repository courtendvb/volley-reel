# バレーボール用 ローカル動画編集アプリ — 設計図 v2

これから新しいアプリをゼロから作る。以下はその要件と設計方針。
まず全体を読み、「最初にやること」の検証から始めてほしい。
技術選定に異論があれば、着手前に理由付きで提案してよい。

> v1 からの主な変更: 複数試合を1リールで扱う／選手は選手IDで同一視する／
> プレーIDに指紋を併用する／注釈・IN/OUT は動画上の絶対時刻で持つ／
> スコアボードと選手テロップの自動表示／出力は 720p・素材のフレームレート／オフセット補正 UI は後回し

---

## 0. v3 の構成変更（M8 のあとの打合せで決定）

```
倉庫（全試合）──チームコードで抽出──▶ プロジェクト（対象チーム・対象試合）
                                         ├ シーン（＝v2 のリール。マーカー1〜5 と並び・IN/OUT・注釈）
                                         └ 動画（シーンを並べたもの）──▶ MP4
```

決定事項:
- **倉庫とプロジェクトは別の場所**。倉庫は試合だけを持つ（`library.json`、`matches/<id>.json`、`cache/`）。
  プロジェクトは好きなフォルダに作り、`project.json` に倉庫の試合IDの一覧と対象チームのコードを持つ
- **DVW と動画は元の場所を参照**（コピーしない）。スカウトの修正は次の読み込みで反映され、M8 の再リンクで追従する
- **シーンは複数の動画で共有する**。シーンを直すと、それを使うすべての動画に反映される
- **作る順番**: ① 倉庫とプロジェクト作成 → ② シーンと動画 → ③ オブジェクト（頂点編集と Office 風の書式）

① の実装（v3/library）:
- 起動画面は倉庫とプロジェクトの一覧。倉庫の試合はチームコード・日付・チーム名で絞り込める
- **フォルダから一括取り込み**: 複数フォルダを走査し、DVW と動画を「日付」と「三文字のチームコード」で組にする
  （例: `2026-10-11 HTH-SMT.dvw` ↔ `261011HTH-SMT_FM.MP4`）。日付とコードが合えば確定、日付だけの一致は要確認として
  チェックを外して出す。同じ日に動画が複数あってコードで決まらなければ組にしない
- DVW の日付は、スカウトした PC の地域設定で dd/mm と mm/dd のどちらにもなる。ファイル名の日付が入れ替えた方と一致すれば、
  ファイル名を採る（実データの `&2024-08-10 … FRA-POL.dvw` がこれに当たった）
- **プロジェクト作成**: 対象チームのコード（例 `HTH, HTA`）を入れると倉庫からそのチームの試合を抽出し、複数選んで作る。
  作成後も「試合」ボタンで足す・外すができる。対象チームのコードはプロジェクトの「自チーム」になる
- **v2 形式のプロジェクト**は開いたときに移行する: 中の試合を同じIDのまま倉庫へ移し（同じ動画と DVW の試合が倉庫にあれば
  そちらを使い、リールの試合IDを付け替える）、古い `matches/` は `matches.v1-<時刻>` に名前を変えて残す

② の実装（v3/scenes）:
- **シーン**は v2 のリールそのもの（`reels/<id>.json`、マーカー・並び・書き出し範囲・長さの初期値・注釈）
- **動画**は `videos/<id>.json`: 名前、シーンIDの並び、オーバーレイ設定（配色・スコアボード・テロップ・タイトルカード）。
  同じシーンを複数の動画に入れられ（動画の欄に「共有 n」と出る）、シーンを直すとそのすべてに反映される。
  シーンを削除すると、それを使う動画から外れる
- タイトルカードは「シーンの頭（シーン名）」と「マーカーの頭（マーカー名）」をそれぞれ選べる
- 通し再生と書き出しは同じ計画（`planVideo`: シーン → マーカーのグループ → クリップ）に従う。クリップの長さは
  **そのクリップのシーンの**初期値で計算する。シーン単体の再生もできる。通し再生中はシーンの編集欄が再生中のクリップの
  シーンに切り替わる
- 新しいシーンは今の動画に入る（動画がなければ最初の動画を作る）
- 元に戻すは、シーンと動画の編集を操作した順に戻す（1つの履歴）
- **移行**: 動画のない既存プロジェクトは、リール1本ごとに同じ名前の動画を作り、リールのオーバーレイ設定を移す
  （シーンの頭のカードはなし）。これまでと同じ単位で書き出せる

③ の実装（v3/objects）:
- 新しい図形: **折れ線**と**多角形**（クリックで頂点、ダブルクリックか Enter で確定、Backspace で1つ戻す、Esc で中止）
- **頂点の編集**（つまみ）: 矢印の両端、四角・円の 8 方向（Shift で縦横比を保つ）、折れ線・多角形・フリーハンドの各頂点。
  辺の中点を引くと頂点が増え、頂点をダブルクリックすると消える（線は 2 点、多角形は 3 点まで）。点の多いフリーハンドは
  「点を減らす」（形を保って間引く）で編集できるようにする。折れ線は「閉じる」で多角形に、多角形は「開く」で折れ線に
- **書式**（Office の図形の書式に近い形）: 線の色・太さ・種類（実線／破線／点線）、塗りの色と透明度（四角・円・多角形）、
  矢印の先（終点／両端／なし）、テキストのサイズ・太字・縁取り・**枠付き**（枠の塗りと透明度、枠線の色と太さ、余白）、
  図形全体の透明度。何も選んでいないときは、次に描く図形の書式になる
- 追加した項目はすべて省略可能で、省略時は以前の見た目。以前に描いた注釈はそのまま表示・書き出しされる
- 書式の欄は高さを固定し、選択が変わっても動画の表示領域が動かないようにした

## 1. 何を作るか

DataVolley のスカウトファイル（.dvw）と試合動画を同期させ、
**選手に見せるハイライト動画（MP4）を作る**ためのローカルアプリ。

VolleyStation の動画機能が下敷き。ただし VolleyStation には次の2つの不満がある。
これを解消することがこのアプリの存在理由。

1. **注釈（テキスト・図）が入れられない。**
   そのため一度 MP4 に書き出し、別の動画編集ソフトで読み込んで注釈を入れる、
   という往復が毎回発生している。
2. **クリップの長さを1本ずつ決められない。**
   「キープレーの何秒前から何秒後」を全クリップ一括でしか指定できない。
   実際は「このクリップは長めに見せたい」「このクリップは前半を切りたい」がある。

### 使う人・環境

- 使うのは**作者1人だけ**。チーム配布・複数人編集・共有はしない
- **Windows**、**オフライン**で動くこと
- 動画は **Sony ハンディカムの MP4**、基本 **720p / 29.97fps**（30000/1001。映像は H.264 4:2:0、音声 AAC — M0 で実素材を確認）
- **1試合 = 動画1ファイル**が基本
- スカウトファイルは**あらかじめ動画と完全に同期済み**のものが用意される
- **音声は不要**。書き出しも音声なしでよい
- 完成リールの長さは**長くて15分程度**
- **1本のリールで複数試合のプレーを使う**ことがある

## 2. 作業の流れ（このアプリの中心）

```
試合を登録する（動画 + .dvw）※複数可
  → 試合を切り替えながら、プレーを検索・絞り込み（選手・スキル・評価・ローテ・セット等）
  → 見せたいプレーを選んでリールに入れる（別の試合のプレーも同じリールへ）
  → マーカー 1〜5 で分類する（マーカーには名前を付けられる）
  → 並べ替える（マーカー同士の順序、マーカー内の順序の両方）
  → クリップごとに IN/OUT を詰める
  → クリップにテキストや図を配置する／スコアボード・選手テロップを調整する
  → MP4 に書き出す
```

**これを1画面で完結させる。** 画面の行き来や、書き出し中に操作を止められることを避ける。

## 3. 機能要件

### 3.1 試合の読み込み

- 動画ファイルと .dvw を選んで「試合」として登録する。試合はプロジェクトに複数持てる
- 取り込み時に ffprobe でコーデックを確認する
  - `codec_name` に加えて **`pix_fmt` も確認**する。4:2:2 / 10bit の H.264 は Chromium で再生できないので、
    その場合は 8bit 4:2:0 に再エンコードする
  - 音声がリニアPCM など Chromium の扱えない形式なら、**音声トラックだけ捨てた**コピーを `cache/` に作る
    （`-an -c:v copy`、再エンコードしない）。XAVC S の LPCM は MP4 内だと再生自体を拒否される可能性がある
  - 音声が AAC など再生できる形式なら、**元の動画をそのまま参照する**（`<video>` は常にミュート）。
    実素材（HTH-SMT、3.7GB、AAC）はこれに当たり、数GBのコピーが不要になる（M1 で確認）
- `offsetSec`（DVW 時刻 + offset = 動画時刻）はデータとして持つが、初期値 0。
  スカウトは事前に同期済みなので**補正 UI は v1 では作らない**（必要になったら「1点合わせ」で足す）

### 3.2 選手・チームの同一性（複数試合で必須）

同じ選手が、試合によってホーム（`*01`）にもアウェイ（`a01`）にもなる。**これは同じ選手とみなす。**

- 選手の識別キーは **`[3PLAYERS-H/V]` の `[8]`（DataVolley の選手ID、例: `YAN-YUR-02`）**
  - 側＋背番号（`*_1`）は試合内の参照にだけ使い、試合をまたぐ識別には使わない
- **正規化**: 末尾の `-a` を外す。
  紅白戦ファイルではアウェイ側がチームコード `HTA`、選手ID `YAN-YUR-02-a` になっている（実データで確認済み）
- 選手IDが空なら `姓|名|背番号` で代用する
- プロジェクトに**名寄せ表**を1つ持ち、自動規則で合わない例外を「この2つは同じ人」と手動指定できる
- **自チーム**はプロジェクト設定でチームコードを登録して判定する（例: `HTH`, `HTA`）。
  検索・表示の軸は「ホーム/アウェイ」ではなく「自チーム/相手」
  - 両側とも自チームの試合（紅白戦）は、ホーム側を「左」として扱う
- 表示名は**英語（DVW の表記）のまま**。日本語表記は持たない

### 3.3 プレーの検索・絞り込み

- 対象の試合を切り替えられる（左パネル上部）
- チーム（自チーム/相手）、選手（選手キーで試合横断）、スキル（S/R/A/B/D/E）、
  評価（# + ! - / =）、セット、ローテーション、開始・終了ゾーンで絞り込める
- 結果をクリックするとそのプレーに飛ぶ
- 絞り込み結果をまとめてリールに追加できる

### 3.4 リール（ハイライト動画1本の設計図）

- リールは試合に属さず、**プロジェクト直下**に置く。1リールが複数試合のクリップを持てる
- リールに入れたプレー（＝クリップ）に **マーカー 1〜5** を割り振る
  - 再生しながら**数字キー 1〜5** で振れること（同じ数字か `0` で解除）
  - マーカーごとに**名前**を付けられる（例: 1=Good reception, 2=Broken plays）
  - マーカーごとに色を変える
- **並べ替え**
  - マーカーのグループ同士の順序（例: 3 → 1 → 2）
  - マーカー内のクリップの順序
- 書き出し範囲を選べる
  - 「マーカー付きだけ」
  - 「全部」（マーカー付きをマーカー順に並べ、その後にマーカーなしを**試合の日付 → 試合内の時刻**順で）
- リールの順に**通し再生**してプレビューできる
  - 試合をまたぐと `<video>` の src を切り替える。M3 の実測では切り替えから映像が出るまで約 0.15〜0.3 秒で、
    プレビューとしては許容範囲のため、`<video>` を2つ持つ先読みは見送った（気になれば後で入れる）
- 同じラリーから複数プレーを入れて範囲が重なった場合は**警告を出すだけで両方残す**（意図的な重複がありうる）
- プレーに紐づかないクリップ（タイムアウト等）は v1 では作らない（`playId: null` で後から拡張できる形にしておく）

### 3.5 クリップごとの IN/OUT（VolleyStation の不満 2 の解消）

- **デフォルトはラリー構造から決める。** 固定秒数で切らない
  - 「ラリー全体」モード: サーブ → **最後のプレー**（＋余白）。得点行の時刻は最後のプレーから約10秒遅れて記録されるので、OUT には使わない
  - 「キープレー中心」モード: キープレー時刻 ± 可変秒
- その上で**1クリップずつ上書き**できる。保存値は**動画上の絶対時刻**
- 操作は**ループ再生しながらキーで詰める**方式。数値入力は補助

| キー | 動作 |
|---|---|
| `[` / `]` | 現在位置を IN / OUT にする |
| `←` `→` | 0.5秒ずつ微調整 |
| `Shift` + `←` `→` | 1フレームずつ（fps は ffprobe の値） |
| `Space` | ループ再生の開始・停止 |

### 3.6 注釈（VolleyStation の不満 1 の解消）

- クリップごとに配置できる: **テキスト**、矢印、円、四角、フリーハンド
- 色・線の太さ・文字サイズを選べる
- **座標は動画に対する正規化座標（0〜1）で保存する。** ピクセルで持たない
- v1 の注釈は**静止**。ただし「いつ出す / いつ消す」の**出し入れだけ**は持たせる
  （ffmpeg の `enable='between(t,a,b)'`）
- **出し入れ時刻は動画上の絶対時刻で保存する。** クリップ先頭からの秒で持つと、
  IN を詰めたときに注釈のタイミングがずれる。書き出し時にクリップ内時刻へ変換する
- 移動するアニメーションは v1 ではやらない

### 3.7 自動オーバーレイ（スコアボード・選手テロップ・タイトルカード）

スカウト情報から自動で生成して焼き込む。**すべての要素を個別に設定できる**こと。

**要素と設定項目**

| 要素 | 内容 | 個別設定 |
|---|---|---|
| スコアボード | 自チームコード / SETS / PTS / 相手コード | 表示 ON/OFF、位置、サイズ、SETS 行の有無、ラリー勝者の強調の有無 |
| 選手テロップ | 背番号 / 名前 / スキル / 評価 | 表示 ON/OFF、位置、サイズ、背番号・名前・スキル・評価それぞれの ON/OFF |
| タイトルカード | マーカーグループの頭に数秒 | 表示 ON/OFF、秒数、マーカー名・試合名（例: `vs SAK 2026-03-14`）それぞれの ON/OFF |

- 通し再生のプレビューでも、マーカーグループの頭にタイトルカードを設定秒数だけ出す
- 位置は6か所のプリセット（左上・上中央・右上・左下・下中央・右下）から選ぶ。
  初期値はスコアボード=上中央、選手テロップ=左下
- 設定は**リール単位**。その上で**クリップごとに**、要素の非表示・テロップ文言の上書きができる
- 表示時間の初期値は「クリップ全体」。3.6 と同じ絶対時刻方式で出し入れを指定できる

**デザイン: 重厚な放送風（M6 のレビューで決定。当初の SyncScout 風から変更）**

- 書体は Bahnschrift の太字。濃いベース色の板に、端を斜めに切ったアクセント色の箱を組み合わせる
- スコアボード: 中央1行で「チーム — 点数 — チーム」、その下に小さく `SET n · n`。ラリーを取った側の点数に
  アクセント色の下線。両端の板は外側を斜めにカット
- 選手テロップ: アクセント色の斜めの箱に背番号、ベース色の板に `LASTNAME` と `SKILL · EVALUATION`
- タイトルカード: 暗い全面に、小さく `VS 相手 · 日付`、その下にアクセント色の番号とマーカー名の板
- **配色は選べる**: プリセット（ブラック × レッド、ネイビー × ゴールド、チャコール × ボルドー、ブラック × ブルー、
  ダークグリーン × ライム）か、ベース色とアクセント色を自由に指定。アクセント上の文字色は明るさで白／黒を自動選択
- 細部は後で詰める前提（ユーザー確認済み）

**データの決め方**

- スコアボードの並びは**自チームが常に左**（3.2）。点数は**ラリー開始前**の値
- 名前は姓（大文字）＋名のイニシャル。同じ姓の選手は名のイニシャルで区別する（既存パーサーと同じ規則）
- スキル・評価の英語表記は**スキルごとの変換表（JSON）**で持つ。同じ `#` でもスキルで意味が変わる
  （例: `S#`=Ace, `A#`=Kill, `A/`=Blocked, `R#`=Perfect）。変換表は手で書き換えられるようにする

### 3.8 書き出し

- ffmpeg で MP4（H.264、**音声なし**）
- 出力は **720p・素材のフレームレート**（29.97fps）。30fps に固定すると約33秒ごとに1フレーム重複する。
  素材のフレームレートが試合ごとに違うときだけ書き出し時に揃える
- クリップごとに: トリム → 注釈・オーバーレイ PNG を overlay → エンコード → concat demuxer で連結
  （全クリップ同じ設定でエンコードすれば継ぎ目は出ない。filter_complex 一本化との比較は M0 で行う）
- 注釈・オーバーレイは Canvas で**書き出し解像度**の透過 PNG に描いて ffmpeg に渡す。
  **プレビューと書き出しで同じ描画関数を使う**（見た目の不一致を防ぐ）
- **バックグラウンドで実行**し、進捗表示とキャンセルができる（`ffmpeg -progress`）。
  書き出し中も他の操作をできること
- 目安: libx264 veryfast・720p で 5〜10倍速 → 15分のリールで 2〜3分

## 4. やらないこと（v1）

- クラウド保存、アカウント、共有URL、複数人編集
- iPad / スマホ対応
- 音声
- 動く注釈（アニメーション）
- クイズ機能
- 自動ハイライト抽出
- LINE 等の送信先に合わせた最適化
- 日本語の選手名表記
- オフセット補正 UI
- プレーに紐づかないクリップ
- 1080p 出力

## 5. 技術方針

| 領域 | 方針 | 理由 |
|---|---|---|
| アプリ | **Electron** + TypeScript | オフライン・ローカルファイル・ffmpeg 実行が必要。配布しないので署名や自動更新は不要 |
| UI | **React** + Vite | 1画面に状態が多い（リール・選択・トリム・注釈・オーバーレイ設定） |
| 動画再生 | HTML5 `<video>` | `requestVideoFrameCallback` でフレーム精度が取れる。YouTube 埋め込みは不可 |
| 注釈・オーバーレイ描画 | **レンダラ側の Canvas**（node-canvas は使わない） | Windows でのネイティブビルドの手間を避け、プレビューと書き出しで同じ描画関数を使える |
| 書き出し | **ffmpeg / ffprobe を同梱** | ffmpeg.wasm は試合単位の処理には遅すぎる |
| 保存 | **プロジェクトフォルダ内の JSON**。試合1つ・リール1本ごとにファイルを分ける | 人間が読めて壊れにくい。同期フォルダでの SQLite 破損を避ける |
| 動画の置き場 | **パスで参照**するだけ。コピーしない | 1試合で数GBある |

ライセンス: libx264 入りの ffmpeg は GPL。個人利用なので問題ないが、配布する場合は注意。

```ts

  playerAliases: Record<string, string> // 選手キー → 代表の選手キー（名寄せの例外）

}

type Match = {
  id: string
  date: string                         // 'YYYY-MM-DD'。リールの時系列並びに使う
  videoPath: string                    // 取り込み後（音声除去済み）のファイル
  dvwPath: string
  offsetSec: number                    // DVW 時刻 + offset = 動画時刻。初期値 0
  fps: number                          // ffprobe の値
  teams: { home: Team; away: Team }
}

type Player = {                        // DVW から毎回パースする
  key: string                          // 正規化した選手ID（末尾 -a を除く）。空なら '姓|名|背番号'
  side: '*' | 'a'
  jersey: number
  lastName: string
  firstName: string
}

type Play = {                          // DVW から毎回パースする。保存しない
  id: number                           // ファイル内の出現順（スキップ規則は固定）
  fingerprint: string                  // `${setNum}|${score}|${code}|${time}`
  time: number                         // DVW の値（offset 適用前）
  side: '*' | 'a'
  jersey: number
  playerKey: string                    // 試合横断の選手識別
  skill: 'S'|'R'|'A'|'B'|'D'|'E'|string
  effect: '#'|'+'|'!'|'-'|'/'|'='|string
  setNum: number
  setsBefore: { home: number; away: number }
  score: string                        // ラリー開始前の "HH-AA"
  homeRot: number | null
  awayRot: number | null
  startZone: number | null
  endZone: number | null
  rallyId: number
}

type Rally = {
  id: number
  serveTime: number
  endTime: number | null
  wonBy: '*' | 'a' | null
}

type Anchor = 'tl' | 'tc' | 'tr' | 'bl' | 'bc' | 'br'

type OverlaySettings = {
  scoreboard:    { enabled: boolean; anchor: Anchor; scale: number; showSets: boolean; highlightWinner: boolean }
  playerCaption: { enabled: boolean; anchor: Anchor; scale: number;
                   showNumber: boolean; showName: boolean; showSkill: boolean; showEvaluation: boolean }
  titleCard:     { enabled: boolean; durationSec: number; showMarkerName: boolean; showMatch: boolean }
}

type Reel = {
  id: string
  name: string
  markerNames: Record<1|2|3|4|5, string>
  groupOrder: (1|2|3|4|5)[]
  groups: Record<1|2|3|4|5|'none', string[]>  // clipId の並び = 順序
  clips: Record<string, Clip>
  scope: 'marked' | 'all'
  overlay: OverlaySettings
}

type Clip = {
  id: string
  matchId: string
  playId: number
  fingerprint: string                  // 再パースで playId が一致しなければこれで探し直す
  inSec: number | null                 // 動画上の絶対時刻。null = デフォルト規則
  outSec: number | null
  annotations: Annotation[]
  overlayOverride?: {
    scoreboard?:    { hidden?: boolean }
    playerCaption?: { hidden?: boolean; text?: string }
  }
}

type Timing = { showFrom?: number; showTo?: number }  // 動画上の絶対時刻

type Annotation = Timing & (
  | { kind: 'text';  x: number; y: number; text: string; size: number; color: string }
  | { kind: 'arrow'; x1: number; y1: number; x2: number; y2: number; width: number; color: string }
  | { kind: 'circle' | 'rect'; x: number; y: number; w: number; h: number; width: number; color: string }
  | { kind: 'freehand'; points: [number, number][]; width: number; color: string }
)
// 座標はすべて 0〜1 の正規化座標
```

**プレーID の扱い**: 再パース後、`playId` のプレーの指紋がクリップの指紋と一致すればそのまま使う。
一致しなければ、次の順に探して `playId` と指紋を更新する（M8）:
1. 指紋が完全に一致するプレー
2. 同じセット・同じスカウトコード・同じ時刻のプレー（得点の追加などで点数がずれた場合）
3. 同じセット・同じスカウトコードで、時刻が 2 秒以内のうち一番近いプレー（時刻を直した場合）

2・3 は候補が1つに決まるときだけ使う。見つからないクリップは「要確認」として UI に出す（勝手に消さない）。
実データ 37 ファイル・約 19,000 プレーで、先頭近くに得点を1本足しても取りこぼしは 0 だった。

## 7. DVW パーサーの仕様（既存実装からの知見）

**参考実装がある**: `C:\Users\heima\code\HTH_videoviewer\dvw-parser.js`（JS、約130行）。
既存の Web アプリで実戦投入済み。読んで移植・拡張してよい。
ただし選手の識別キーは `${side}_${num}` から**選手ID**に置き換えること（3.2）。
実データの .dvw も同じフォルダに多数ある（紅白戦の `_all home` を含む）。

Python の `openvolley/pydatavolley`、R の `openvolley/datavolley` も参考になる。

ファイルはセクション `[3XXXX]` で区切られたテキスト。使うのは次の3つ。

**`[3TEAMS]`** — 1行目がホーム、2行目がアウェイ。`;` 区切りで `[0]`=チームコード、`[1]`=チーム名。

**`[3PLAYERS-H]` / `[3PLAYERS-V]`** — `;` 区切り。`[1]`=背番号、`[8]`=**選手ID**、`[9]`=姓、`[10]`=名。

**`[3SCOUT]`** — 1行1イベント。`;` 区切りで `[0]` がスカウトコード、`[9]`=ホームのローテ、
`[10]`=アウェイのローテ、`[12]`=**動画時刻（秒）**。

スカウトコード `c[0]` の文字位置:

| 位置 | 意味 |
|---|---|
| 0 | チーム（`*`=ホーム, `a`=アウェイ） |
| 1-2 | 背番号 |
| 3 | スキル（`S`サーブ `R`レセプション `A`アタック `B`ブロック `D`ディグ `E`セット。実データには `F` フリーボールもあるが、今のパーサーは読まない） |
| 4 | 種類／テンポ |
| 5 | 評価（`#` `+` `!` `-` `/` `=`） |
| 6-7 | コンビネーションコード |
| 9 | 開始ゾーン |
| 10 | 終了ゾーン |
| 11 | 終了サブゾーン（A〜D） |
| 12 | 打ち方 |
| 13 | ブロック枚数 |

特殊な行:
- **得点**: `*p` または `ap` で始まり、`HH:AA` 形式のスコアを含む。`[12]` がその時刻＝**ラリー終了**
- **セット終了**: `**` で始まり `set` を含む
- **ラリー開始**はサーブ（スキル `S`）の行

注意:
- ローテが空の行は直前の値を引き継ぐ
- 動画時刻が無い行はスキップ（ID がずれないよう、スキップ規則は固定すること）
- 最終セットはセット終了マーカーなしで終わることがある
- **得点行の `[12]` は最後のプレーから約10秒遅れる**（M0 で確認）。ラリーの終わりは最後のプレー時刻で判断する
- **`_all home` のファイルは両チームとも `*` で入力されている**。`*`/`a` でチームを分けられないので、
  試合ごとに「全部ホーム入力」の印を持ち、自チーム/相手の絞り込みを無効にする。得点側は点数の増え方で判定する
- 紅白戦などで**動画時刻が約2時間から始まる**ファイルがある。取り込み時に DVW の時刻範囲と動画の長さを照合する
- DVW の時刻は**秒単位**。レセプションとアタックが同じ秒に記録されることがある

## 9. 最初にやること: 書き出しの検証（2日）

**UI を作る前に、一番不確実な書き出しを単体スクリプトで検証する。**

検証スクリプトの内容:
1. 実際の Sony ハンディカムの MP4 を1本読む（ffprobe で `codec_name` / `pix_fmt` / fps を確認、音声除去）
2. .dvw をパースし、適当なプレーを5本選ぶ（**別の試合から1本以上**混ぜる）
3. 各クリップに、テキスト1つ・矢印1つ・スコアボード・選手テロップを PNG に描く
   （検証スクリプトではビルド不要の `@napi-rs/canvas` でよい。アプリ本体はレンダラの Canvas）
4. ffmpeg で トリム → overlay（うち1本は `enable` で途中から表示）→ 連結 → 音声なし MP4
5. 測る: 処理時間、画質、注釈のにじみ、クリップ境界の継ぎ目、ファイルサイズ

合格基準:
- 720p で、素材の長さに対して 3倍速以上で書き出せる
- 注釈・スコアボード・テロップの線と文字がボケない
- クリップの切れ目（試合をまたぐ切れ目を含む）に黒フレームやフリーズがない

## 11. 開発時の注意

- **実データで確かめる。** 想定や記憶で判断せず、実際の .dvw と動画で計測してから決める
- DVW のパースは**同じファイルなら必ず同じプレーIDになる**こと。加えて指紋で再リンクできること
- 選手は**選手キー**で扱う。`*01` / `a01` を別人として扱うコードを書かない
- 時刻は**動画上の絶対時刻**で保存する。クリップ内時刻への変換は書き出し・プレビューの直前だけで行う
- 動画のシーク・再生制御は1か所にまとめる。
  複数の箇所が勝手に再生位置を動かすと「選んだクリップが別の場面に飛ばされる」不具合になる
- 注釈・オーバーレイの描画関数はプレビューと書き出しで共通にする
- 保存はこまめに自動で。作業中にアプリが落ちても失わないこと
  （M8: 一時ファイル → fsync → 旧版を .bak → rename。読めなければ .bak から復元。ウィンドウを閉じる前に保存待ちを書き出す）
- Chromium は、ウィンドウが隠れる（他のウィンドウの裏も含む）と**ミュートで音声なしの動画を一時停止**する。
  通し再生が止まるので、`disable-background-media-suspend` と `CalculateNativeWinOcclusion` の無効化、
  `backgroundThrottling: false` で抑えている（M3 で再現・確認）
