# Product site

A static page in two languages: `index.html` (English) and `ja.html` (Japanese), with a switch in the nav.
Both share `site.css` and `site.js` (the court layer tabs and the film's chapter buttons). Open either file in a browser; nothing to build.

## Taking screenshots again

`source/shoot-2026-11/` holds the scripts. Start the built app with its own library and profile so your own settings stay untouched:

```bash
VR_LANG=en VR_LIBRARY=<scratch>/lib npx electron . --remote-debugging-port=9333 --user-data-dir=<scratch>/userdata
```

Add `--inspect=<port>` to export without the save dialog: replace `dialog.showSaveDialog` in the main process with one that returns a fixed path, then press Export in the app. Then drive it from that folder: `node cdp.mjs js "<js>"`, `node cdp.mjs shot shots/<name>.png`, and `shoot.sh <name> '<row regex>' '<setup js>' <seconds after the key play>` to pause on a play and crop the video frame. `crop.py` crops the video area out of a full-window shot.

`drag.mjs <x0> <y0> <x1> <y1>` drags across the video as fractions of its size (0 to 1), which is how the circle on the block was drawn after picking the Circle tool. Confirm dialogs (such as deleting a match) freeze the page for these scripts, so restart the app instead of using them.

The other files in `source/` (`make_dvw.py`, `add_annotations.py`, `set_corners.py`, `crop_frames.py`, `cdp.mjs`, `lib.js`) are from the first version of the page.

## Downloads

The two download buttons (top and bottom) and the list of builds are filled in by `site.js` from the latest release of `courtendvb/syncscout-video-editor-releases` (GitHub's public API, no key): the Windows `setup-*.exe`, and the Mac `arm64.dmg` and `x64.dmg`. A Windows browser gets the Windows installer; a Mac browser that can tell its chip (Chromium) gets the matching disk image; Safari and Firefox cannot, so the button points to the list and the person picks (the page explains how to look it up); phones, tablets and Linux get the list and a note to use a computer. If the API is unreachable the links open the release page. The Mac build is not signed by Apple, which the page says too. The names it looks for are in the regular expressions in `site.js`, so keep the file names in `electron-builder.yml` in that shape.

## Manual

`manual/ja/` holds the Japanese manual, linked from the nav of `ja.html`: an index and one page for each of the 11 chapters. The pages share `manual/manual.css` on top of `site.css`, and their screenshots are in `manual/img/ja/`; chapters 6-8 also use the site's own `img/` shots (court layers, the finished clip and card, slides, report, analysis, preset). They were shot from the built app in Japanese with its own library and profile (as in "Taking screenshots again"), on four matches of the fictional Riverside Herons from `source/make_demo_dvw.py` with a stand-in video made from `source/still-*.jpg`. The accounts were off in that build so the library could hold four matches; the sign-in screen was shot with them on. The pages are plain HTML written by `manual/source/gen.py`, which holds each chapter's body and gives every page the same header, chapter list and previous / next links: edit the chapter there and run `python site/manual/source/gen.py`, rather than editing the HTML.

## Pricing

The Pricing section (`#pricing`) is plain text, not read from Stripe: US dollars, the same plans as the SyncScout page (https://syncscout.courtend.net/#pricing), since one subscription covers both. When the prices or the trial change there or in Stripe, change both pages here by hand. Its buttons lead to the download, never to Stripe: a purchase has to be tied to the signed-in account and its team, which only the app's checkout does. The footer links to SyncScout's terms, privacy and refund pages and its contact address.
