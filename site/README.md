# Product site

A static page in two languages: `index.html` (English) and `ja.html` (Japanese), with a switch in the nav.
Both share `site.css` and `site.js` (the court layer tabs and the film's chapter buttons). Open either file in a browser; nothing to build.

## Taking screenshots again

`source/shoot-2026-11/` holds the scripts. Start the built app with its own library and profile so your own settings stay untouched:

```bash
VR_LANG=en VR_LIBRARY=<scratch>/lib npx electron . --remote-debugging-port=9333 --user-data-dir=<scratch>/userdata
```

Add `--inspect=<port>` to export without the save dialog: replace `dialog.showSaveDialog` in the main process with one that returns a fixed path, then press Export in the app. Then drive it from that folder: `node cdp.mjs js "<js>"`, `node cdp.mjs shot shots/<name>.png`, and `shoot.sh <name> '<row regex>' '<setup js>' <seconds after the key play>` to pause on a play and crop the video frame. `crop.py` crops the video area out of a full-window shot.

`drag.mjs <x0> <y0> <x1> <y1>` drags across the video as fractions of its size (0 to 1), which is how the circle on the block was drawn after picking the Circle tool. Confirm dialogs (such as deleting a match) freeze the page for these scripts, so restart the app instead of using them.

The other files in `source/` (`make_dvw.py`, `add_annotations.py`, `set_corners.py`, `crop_frames.py`, `cdp.mjs`, `lib.js`) are from the first version of the page.

## Downloads

The two download buttons (top and bottom) and the list of builds are filled in by `site.js` from the releases of `courtendvb/syncscout-video-editor-releases` (GitHub's public API, no key), each file from the newest release that has it: patch releases carry only the Windows build, and the Mac build comes with minor versions and up: the Windows `setup-*.exe`, and the Mac `arm64.dmg` and `x64.dmg`. A Windows browser gets the Windows installer; a Mac browser that can tell its chip (Chromium) gets the matching disk image; Safari and Firefox cannot, so the button points to the list and the person picks (the page explains how to look it up); phones, tablets and Linux get the list and a note to use a computer. If the API is unreachable the links open the release page. The builds are not signed (no paid Windows certificate, no Apple developer ID), so under the list two folding notes explain the first start: Windows SmartScreen's More info, Run anyway, and on Mac a Terminal line (with a copy button, `[data-copy]` in `site.js`) that downloads the newest `*-<arch>-mac.zip` among the releases with curl, unpacks it with ditto into /Applications and opens it. A file curl downloads carries no quarantine, so macOS doesn't stop it; the same line is run on the Mac build in `.github/workflows/mac.yml`, so keep the two the same. The names it looks for are in the regular expressions in `site.js`, so keep the file names in `electron-builder.yml` in that shape.

## The how-it-works animation

The figure in the court section (.auto, one 12 s CSS loop, no script) stacks the plain frame (img/before.jpg), an SVG of the grid and four corner dots, a scan band, and the finished frame (img/after.jpg, img/ja/after.jpg). The SVG's corners are the fitted court of the film's match (court.corners in its library JSON, as fractions of the 1280 x 720 picture); the grid lines are that quadrilateral cut in thirds with a perspective transform, so they sit on the court lines. With reduced motion it rests on the finished picture. If the film's block clip (and so fter.jpg) changes, the plain frame, the SVG and the finished frame still need to be the same moment of the same match.

## Publishing

The site lives at https://editor.courtend.net/, on the same rented server as courtend.net. `.github/workflows/site.yml` uploads it over FTPS whenever `site/` changes on main (or by hand: Actions > Site > Run workflow), with the FTP details in four repository secrets named in that file. It sends everything in `site/` except `README.md`, the `source/` folders and `media/`. The server lets browsers keep CSS and JS for a week, so on the way up every page's links to `site.css`, `site.js` and `manual.css` get `?v=` and the start of that file's hash: a changed file is fetched again at once. Keep those links plain in the repository.

The film (`media/film-en.mp4`, `media/film-ja.mp4`) is not in git, so after making a new one, upload those two files to `media/` on the server by hand. The upload remembers what it sent in `.ftp-deploy-sync-state.json` on the server, so later runs send only changed files and delete only files it sent itself; anything put there by hand is left alone.
